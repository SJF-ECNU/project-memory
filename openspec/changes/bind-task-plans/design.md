# 任务计划书绑定机制任务计划书

关联工作流：[[project-memory/工作流/服务设计文档模板]]。

## 目标与范围

将上一轮按需使用的服务设计模板扩展为每个后续任务固定绑定的任务计划书机制。用户已明确要求；适用单位为现有有界工作流，不是每条聊天消息或每个执行步骤。

交付协议、通用模板、初始化与日常 Skill 指引、导航及本任务的实际关联。不修改桌面 UI，不向其他仓库同步，不追溯编造旧任务的计划或证据。

## 总体方案与职责

计划书保存目标、范围、方案、步骤、验收和步骤状态；工作流保存简短当前摘要与下一步；只追加工作记录保存当次执行证据。三者通过既有工作流标识和普通文档链接关联，不新增数据库、Hash 或审批 Gate。

默认计划路径为 `project-memory/任务计划/<工作流文件名>.md`。有适用的 OpenSpec design.md 或已有计划时复用原路径并补足核心内容；OpenSpec tasks.md 继续保存变更任务清单，计划引用它而不另写竞争的清单。本任务直接用本文作为计划书。

通用模板来自参考文档的论证顺序，但将服务调度内容设为按需章节。小任务至少写清目标和范围、方案、可验证步骤、进度和未决项。运行恢复、并发、库表、接口和容量仅在实际存在时展开。

## 执行与进度

唯一执行清单见 [tasks.md](tasks.md)。每项完成后填写验证证据；工作流只摘要当前进展。范围或方案发生变化时更新本文，原因记入新的工作记录。恢复旧工作流时先补绑定，保留所有历史记录。

## 验收

- 从本任务工作流能够打开本文，并进入执行清单和完成证据。
- 初始化源资产与本仓库本地副本都能引导新建、接管、更新、收尾到同一份计划。
- 以新小任务、已有 OpenSpec 任务、缺计划的旧任务进行文档接管模拟；链接可解析，旧记录不变。
- OpenSpec 严格校验、Skill 校验和本次差异空白检查通过；不据此声称桌面 UI 或真实新仓库初始化已验收。

## 未决项与边界

本次范围内无待用户决定事项。模板和协议由 Agent 执行，不是运行时强制校验；桌面专用计划入口不在本次范围内。

## 当前结果

执行清单已完成，关联证据见 [[project-memory/工作记录/2026/10/任务计划书绑定机制]]。下一步在新任务中使用绑定流程；本次未同步其他仓库或修改桌面入口。
