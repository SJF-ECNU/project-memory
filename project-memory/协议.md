# 项目记忆协议

本协议在不同代码智能体、模型、客户端和会话之间保存任务进度，同时保证当前 Git checkout 仍是事实来源。

## 事实来源优先级

1. 实时命令结果、Git、当前代码和配置。
2. 当前 OpenSpec、已接受设计和可执行脚本。
3. 持续维护的仓库说明、安装文档和运行手册。
4. 项目记忆摘要与带时间戳的工作记录。

工作记录只证明某位参与者在特定时间观察和验证过什么，不能证明现在仍成立。项目记忆、文档关系层、项目本地 Skill 与入口文件都随当前 Git checkout 切换；跨分支共享使用正常 Git 合并，不维护外部“最新记忆”。

## 哪些工作需要记录

受版本控制的产物发生改变、诊断或决策得到验证，或工作停在下一位参与者必须继承的边界时记录。普通问答和未形成持久结论的探索不记录。

每个有界目标使用一个工作流；每次有意义的完成、阻塞、取消或移交创建一篇只追加工作记录。并行智能体使用不同工作流，不共同编辑同一篇状态日志。

## 任务计划书

每个有界任务（一个工作流）必须绑定一份任务计划书，在开始实质执行前创建或复用。默认从 `project-memory/模板/任务计划书模板.md` 创建到 `project-memory/任务计划/<工作流文件名>.md`；已有计划或适用的 OpenSpec design.md 则沿用原路径，补齐核心内容，不重复复制方案。计划与工作流使用相同的 `workstream` 标识，工作流的“任务计划书”小节链接唯一计划。

计划至少包含目标与范围、总体方案、可验证步骤、步骤状态和未决项。复杂任务再展开职责、数据流、调度、状态恢复、数据接口和容量；小任务可合并章节，不强行套服务架构。已有 OpenSpec tasks.md 时，计划链接该执行清单，不维护重复步骤表。

接管时先读绑定计划，再读最近工作记录，并以当前事实核对。每次关键进展、阻塞或范围变化，更新同一份计划的步骤状态与证据，并同步工作流的当前摘要、阻塞和下一步。新的工作记录必须在“任务计划书”中链接该计划，并注明本次推进的步骤；完成、取消或移交按实际结果更新状态，不将未验证步骤标为完成。

旧工作流再次启动时补齐计划和绑定，注明依据当前证据补建，不改写历史工作记录；已结束任务不批量补写。普通问答不创建工作流或计划。计划用于执行和接续，不增加单独审批流程。

## 接管

1. 从 `project-memory/首页.md` 进入，读取项目概览与任务相关的详细笔记。
2. 选择相关工作流，先读其绑定的任务计划书，再读目标、状态、结果、阻塞、下一步和最近记录；仅在信息不足时继续追溯旧记录。
3. 打开关联的 README、OpenSpec、源码、配置或安装说明。
4. 核对 Git 分支、工作区和当前实现；发现矛盾时明确写出后再继续。

## 持久事实刷新

项目规则、架构、部署方式或其他持久事实变化时，先完整阅读受影响的权威来源，再更新相关稳定记忆和文档索引。静态说明、构建产物和历史测试不能写成实时健康、已安装状态或发布授权。

## 收尾

1. 根据工作记录模板在 `project-memory/工作记录/YYYY/MM/` 创建新文件。
2. 记录经过验证的结果和有界证据，链接规范、差异、报告或源码，不复制长篇原文。
3. 更新受影响工作流的状态、结果、阻塞、下一步和至多五篇近期记录链接。
4. 检查元数据、链接、敏感信息和剩余工作；下一位参与者无需原对话即可继续时才完成。

## 元数据与敏感信息

工作记录只记录运行环境明确提供的值；未知使用 `unknown`，不可用使用 `unavailable`，没有提交使用 `null`。不得记录凭据、Token、Cookie、密码、私钥、密钥值、完整环境文件、敏感报文、私有产物内容或原始命令输出。
